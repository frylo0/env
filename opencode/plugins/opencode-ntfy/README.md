# opencode-ntfy

Плагин OpenCode для отправки коротких уведомлений в [ntfy](https://ntfy.sh). Помогает заметить, что OpenCode закончил работу или ждёт ответа.

## Возможности

- `done` — выполнение основного сеанса завершилось; дочерние сеансы не уведомляют.
- `ask` — OpenCode создал форму вопроса (`form.created` с `metadata.kind: "question"`).
- `perm` — OpenCode ждёт разрешения на действие.
- Уведомления отправляются обычным HTTP POST с текстом без кнопок и ссылок.
- Ошибки сети и ответы HTTP с ошибкой не прерывают работу OpenCode.

Плагин не отправляет уведомления о простое сеанса. Плагин предназначен только для OpenCode v2.

## Быстрый старт

1. Убедитесь, что сервер ntfy доступен OpenCode, а плагин `opencode-ntfy` установлен и загружается OpenCode.
2. Создайте отдельную длинную случайную тему для проекта. Не используйте угадываемое имя вроде `my-project` для публичной темы.
3. Подключите плагин и добавьте настройки в `opencode.jsonc` (OpenCode v2):

```jsonc
{
  "plugins": [
    {
      "package": "opencode-ntfy",
      "options": {
        "server": "https://ntfy.frylo.org",
        "topic": "project-topic-use-a-long-random-value",
        "messages": {
          "done": "✅ done",
          "ask": "💬 ask",
          "perm": "🔐 perm"
        }
      }
    }
  ]
}
```

Для локального каталога плагина укажите его путь в `package` относительно файла конфигурации (например, `"package": "./plugins/opencode-ntfy"`). Плагин экспортирует v2-определение с `id` и `setup` и подписывается на события сервера через v2 API. Не подключайте один и тот же локальный плагин одновременно через auto-discovery и абсолютный путь: в некоторых версиях v2 это создаёт дубликат и опции могут не попасть в активный экземпляр.

4. Подпишитесь на тему в приложении ntfy или откройте её в веб-интерфейсе.
5. Перезапустите OpenCode и проверьте отправку командой из раздела [Проверка](#проверка).

Названия событий и сообщения настраиваются целиком: можно использовать любой короткий текст и emoji. `topic` обязателен. Если не задан, плагин отключается без отправки уведомлений. По умолчанию сервер — `https://ntfy.frylo.org`. В `server` обязательно указывайте схему целиком — `https://` или `http://`; плагин не подставляет её автоматически. Для открытых сетей используйте HTTPS.

При `"debug": true` плагин пишет INFO-диагностику жизненного цикла: запуск, конфигурацию (без темы), типы событий, фильтрацию завершения сеанса и результаты POST-запросов. Токен и текст уведомления не записываются. Диагностика также дублируется в `${TMPDIR:-/tmp}/opencode-ntfy-debug.log`. По умолчанию debug выключен и диагностические логи не пишутся.

## Токен доступа

Для публичной записи токен не нужен. Если сервер требует авторизацию, задайте `NTFY_TOKEN` в окружении **процесса OpenCode**:

```sh
export NTFY_TOKEN="токен-доступа"
opencode
```

Токен отправляется только в заголовке `Authorization: Bearer …`; не добавляйте его в `opencode.jsonc`. Если имя переменной отличается, укажите его в параметре `tokenEnv`.

> Любой, кто знает адрес публичной темы, потенциально может публиковать в неё. Используйте непредсказуемое имя темы или настройте авторизацию на сервере.

## Проверка

Проверьте сервер и тему напрямую, не запуская OpenCode:

```sh
curl --fail \
  -H 'Content-Type: text/plain; charset=utf-8' \
  --data-binary '✅ done' \
  'https://ntfy.frylo.org/<ваша-тема>'
```

С токеном:

```sh
curl --fail \
  -H "Authorization: Bearer $NTFY_TOKEN" \
  --data-binary '🔐 perm' \
  'https://ntfy.frylo.org/<ваша-тема>'
```

Запуск тестов плагина из этой директории:

```sh
npm test
```

## Устранение неполадок

- **Уведомлений нет:** проверьте, что плагин загружен, `topic` задан и OpenCode может достичь `server`.
- **HTTP 401/403:** проверьте токен и права публикации на тему.
- **Не приходит `done`:** отправляется по v2-событиям `session.execution.succeeded`, `session.execution.failed` или `session.execution.interrupted`, только после проверки, что сеанс не дочерний.

Ошибки конфигурации, сетевые ошибки и неуспешные HTTP-ответы записываются в журнал OpenCode. Диагностика не включает токен, тему или текст уведомления; для HTTP-ошибки указывается статус ответа.
